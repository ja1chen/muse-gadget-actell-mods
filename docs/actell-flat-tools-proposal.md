# Actell 一级工具与独立输入改造方案

状态：原始提案，保留用于方案对照。当前实现以[正式共享契约](protocol/FLAT-TOOLS-1.md)及[接入状态](actell-flat-tools-integration-status.md)为准；下文估算和待定接口不是最终实施结果。

## 目标与边界

- Muse 直接发现并调用手机工具，不再学习 RPC 操作、运行会话和取图步骤。
- 截图一次调用返回实际图片及必要元数据；输入操作不要求先截图，不携带截图身份字段。
- 保留 Actell 原始工具后缀，统一增加 `actell.` 命名空间，避免与其他设备工具冲突。
- 不保留 `actell.rpc`、`actell.image`、`actell.view` 兼容入口。设备内部仍可使用现有 RPC 传输，不代表继续向模型暴露 RPC。
- 配对、Wi-Fi、TLS hostname/pin、HMAC、权限范围、审批、截止时间、去重和禁止自动重放保持有效。
- 保留现有头像、字体、TTS 和完整配置，不重置配对，不自动提交或合并分支。

## 当前差异与 Actell 适配结论

已核对的 Actell 源码中，模型工具层不要求模型提供截图 ID，参考图也不因单纯经过一段时间而失效；但点击、拖动内部仍依赖参考图尺寸。

Muse 接入的远程服务层则仍要求 `observation`，其中包含图片 ID、代次及缩略图几何版本，并检查归属与时效。因此，仅修改 Gadget 注册描述无法实现输入独立于截图。

结论：本方案需要 Actell 适配。应由 Actell 提供独立于截图的输入坐标能力，并同步调整远程入口和实际执行路径；不通过伪造图片 ID、隐式截图或关闭身份校验绕过现有检查。对端实际开发分支和已安装版本由 Actell 方评审时重新确认，本次源码核对不代表手机已部署这些行为。

## 面向 Muse 的工具契约

以下为拟定接口，类型和约束需要 Muse 确认可由设备工具注册、正确传递。

| 工具 | 必填参数 | 可选参数 | 成功结果 |
|---|---|---|---|
| `actell.screenshot` | 无 | 无 | 实际 JPEG 图片、宽高、坐标约定、调用标识 |
| `actell.tap` | `x: integer, y: integer, purpose: string` | 无 | 动作执行回执、调用标识 |
| `actell.drag` | `from_x, from_y, to_x, to_y: integer; duration_ms: integer; purpose: string` | 无 | 动作执行回执、调用标识 |
| `actell.home` | `purpose: string` | 无 | 动作执行回执、调用标识 |
| `actell.list_apps` | 无 | 无 | 可见应用名称、bundle ID、版本 |
| `actell.launch_app` | `bundle_id: string, purpose: string` | `arguments: string[]` | 启动回执、调用标识 |
| `actell.type_text` | `text: string, purpose: string` | 无 | 输入回执、调用标识 |
| `actell.wait` | `duration_ms: integer` | 无 | 等待完成 |
| `actell.call_status` | `operation_id: string` | 无 | 原调用状态及可用结果，不重新执行 |

最后一个是 Gadget 增加的查询工具，没有对应的 Actell 原始模型工具；内部映射到原运行/调用的查询接口。其必要性是：不再暴露通用 RPC 后，仍需给不确定结果提供核对入口。

工具参数不包含 `run_id`、`call_id`、`image_id`、`generation`、`geometry_revision`。内部仍可保留这些标识用于日志、缓存、去重和审计；不要求模型转抄。

拟定约束沿用当前能力：拖动 100～2000 ms；等待 1～3000 ms；文本不超过 8192 UTF-8 字节；启动参数最多 32 个，具体长度限制由双方契约与现有实现一致维护。`purpose` 是简短公开操作目的，不是模型推理过程。截图中的文字作为不可信内容，不作为工具指令。

`launch_app.arguments` 的数组类型必须核实平台支持；若不支持，由三方选择省略该可选能力或制定明确的字符串编码参数，不能宣称数组已经可用。

## 输入坐标：拟采用 0～1000 整数归一化坐标

这是待三方确认的新约定，不是当前远程接口已经支持的格式。

- 左上角 `(0,0)`，右下角 `(1000,1000)`，横向为 x、纵向为 y。
- 坐标范围是设备当前可交互显示区域，由 Actell 定义并映射到真实输入服务；不是 App 内容区或缩略图局部区域。
- 模型看到全屏图片时，可按 `x = round(pixel_x * 1000 / (width - 1))`、`y = round(pixel_y * 1000 / (height - 1))` 换算；图片缩放不改变归一化坐标。
- Actell 根据独立获取的当前显示几何和方向完成映射，不依赖先前截图对象或截图尺寸缓存。
- 对于不是同一全屏坐标范围的裁剪、旋转、镜像或带边框图片，不能套用上述公式。截图生产端必须先标准化到约定显示区域，或者明确拒绝不支持的变换。
- 普通页面内容变化不使输入坐标协议失效，也不强制重新截图。方向、显示区域或输入路由变化属于几何变化，Actell 在实际执行前更新映射；执行过程中变化且无法一致处理时，返回明确错误，不自动补做动作。
- 如果当前路由无法在不截图的情况下获取可靠显示几何，应明确返回 `geometry_unavailable`；不得偷偷截图，也不得猜测尺寸。
- 几何变化后旧画面上的目标可能已经移位。工具不会保证目标语义仍相同；Muse 根据任务决定是否重新观察，不为每次输入强制截图。

归一化坐标的取舍：参数简单、脱离截图大小，但相对超高分辨率像素有量化误差。Actell 与 Muse 应确认 1001 个位置的精度足够；若不足，在实施前统一提高范围，不能两端各自选择。

示例：

```json
{"tool":"actell.screenshot","arguments":{}}
{"tool":"actell.tap","arguments":{"x":500,"y":750,"purpose":"打开目标项目"}}
{"tool":"actell.drag","arguments":{"from_x":500,"from_y":800,"to_x":500,"to_y":250,"duration_ms":400,"purpose":"向下浏览列表"}}
{"tool":"actell.type_text","arguments":{"text":"测试内容","purpose":"填写已聚焦的文本框"}}
```

以上是工具选择与参数示意，不是要求平台新增一个 `tool/arguments` 外层协议。输入前不隐式点击、不自动切换 App、不附带 Return；截图不自动触发输入。

## 固件内部运行与结果管理

- 固件处理能力协商、运行会话创建/复用、截止时间、提交及轮询。模型不调用 `capabilities`、`runs.open` 或 `calls.get`。
- 同一配对客户端的操作串行执行。已有执行中的调用必须先核对；不能为了新请求取消、抢占其他客户端或未知归属的运行会话。忙碌时返回明确状态，不无限排队。
- 截图内部执行 capture → wait → fetch，成功必须返回实际可供 Muse 识别的 JPEG；元数据成功不能替代图片成功。保留图片大小、格式和边界校验。
- 每次执行有稳定且不含秘密的 `operation_id`，绑定原平台 invoke ID 和原 Actell run/call ID。重复投递同一 invoke 不产生第二次动作。
- 同一次内部提交使用固定语义和标识；每个网络请求仍使用新请求 ID、nonce 和时间戳。断线不能触发新动作提交。
- 在接受或发送可能产生动作的请求前，先保存核对所需的映射。当前 Gadget 仅保留 64 条 RAM 记录并循环回收，不提供重启后的本地历史恢复；Actell 自身 journal 语义不变。
- 结果拟包含 `operation_id`、`state`、`result` 或公开错误。状态至少区分 `succeeded`、`failed`、`pending`、`unknown`；失败与不确定不得混用。网络等待必须小于平台调用超时，留出结果回传余量。
- 返回 `pending/unknown` 后，Muse 通过 `actell.call_status` 查询原调用。查询不重放动作；`not_found` 不证明未执行。即使原平台回执丢失，也需能用平台原 invoke ID 查询；Muse 平台必须确认能否将该 ID 提供给模型或执行器。
- 若平台不暴露原 invoke ID 且首次回执完全丢失，模型可能拿不到 operation ID；三方需明确此时的人工核对或平台查询机制，不能假称已实现端到端可靠恢复。
- 查询截图原调用时，若图片仍有效可返回原图，不重新截图；图片已清理则明确返回结果元数据及 `image_unavailable`。
- 运行会话到期、应用取消和设备断线的收尾由各端按既有权限和生命周期处理；禁止借收尾逻辑自动重新执行或删除配对。

## Actell 所需修改

1. 能力协商明确支持新的归一化坐标及截图独立输入语义。现有能力不能仅凭工具名称判断为兼容；不匹配时返回明确版本/能力错误。
2. 远程 `tap/drag` 不再强制携带 `observation`，不再以图片存在或图片时效为输入准入条件；使用当前输入路由的显示几何。
3. 调整内部 ActionCoordinator/输入执行路径，将授权引用与图片引用分离。取消、审批摘要、截止时间、调用归属和动作去重仍必须绑定真实动作和最终映射参数。
4. 截图继续按既有有界 JPEG 链路返回实际图像，并明确其显示区域与归一化坐标的对应关系。截图 ID 可留在内部协议和回执中。
5. 保持现有运行/调用查询能力，明确失败、未完成、结果未知和图片过期的语义。
6. 核对 Actell 自身模型工具的坐标说明。是否一起切换坐标单位由 Actell 明确决定；若保持像素坐标，内部必须使用独立显示几何并与远程入口显式区分，避免同名参数静默改变含义。

## Muse 所需确认或适配

- 能发现并直接调用上述一级工具，正确处理 integer、string 及可选数组参数；注册刷新后不继续选择已经移除的入口。
- `actell.screenshot` 一次工具调用的混合结果可以同时包含真正可见的图片和结构化元数据；确认与现有 JPEG-base64 设备结果的实际解析行为。
- 同意归一化坐标的范围、方向和换算方式，并根据实际图片确定目标。
- 工具结果中的成功仅代表执行回执；是否达成用户目标需要另外判断，必要时再截图观察。
- 对动作超时不自动发起新动作，使用原 operation ID 核对；确认原平台 invoke ID 的可获得性和截图查询返回图片的支持情况。

实施前使用目标板实际公开功能开关和合成身份运行官方注册序列化器，分别统计每个工具、公共设备工具和外层消息。不能读取或输出真实秘密配置。

- 工具说明删除重复协议细节；每个参数保持准确的类型、单位和必要范围。
- 输入工具不再注册截图身份和运行管理参数，预算预计减少，但必须实际测量。
- 完整注册消息必须留出 cJSON 预分配打印的终止符/内部余量，以及允许的设备名称、版本等可变字段空间；不能把 8191 字节当作安全通过。
- 以覆盖最大允许字段长度的测试和明确余量作为门槛。若不足，优先缩短重复描述；修改 SDK 注册缓冲区需另行说明内存和传输影响，不能静默扩容。
- 原有设备工具按实际板卡能力注册；不因预算问题随意移除用户已有能力。

## 验收与实施门槛

三方确认后才执行以下步骤，当前不触发手机操作：

1. 合成协议测试：能力协商、参数校验、坐标映射、方向/路由变化、越界和几何不可用。
2. 主机测试：内部会话、审批等待、超时、同 invoke 重投、丢回执、断线及重启核对；证明不重复提交动作。
3. 注册验证：目标板功能组合、最大允许字段、九个工具的逐项字节数、参数在平台侧的实际可用性。
4. 目标编译：现有完整配置保持开启；独立确认头像、字体、TTS、手机活动动画与图片链路。
5. 经用户授权后仅更新应用固件，保留 NVS、配对和资源；不用配对重置作为联调手段。
6. 真机验收：Muse 一次调用看到截图；未截图时可执行获准输入；一张截图后可连续操作；缩放和方向映射正确；输入不隐式截图；断线不重放；查询原调用有效。
7. 真机涉及截图外发和输入时，使用已明确授权的非敏感测试页面及动作，分别记录图片可见、输入送达和视觉目标达成，不能互相替代。
8. 同步正式协议、扩展说明、Muse 使用说明、中英文 README 及两份 SDK 差异索引；将本方案标为已确认/已实施或注明剩余差异。

## 请三方反馈

请针对同一份方案逐项答复“同意 / 需调整 / 不支持”，尚未答复不视为批准：

| 评审方 | 需要确认的事项 |
|---|---|
| Muse | 一级工具命名与参数类型；单调用图片加元数据；归一化坐标；原 invoke ID 可获得性；超时后状态查询 |
| Actell | 输入脱离截图；独立显示几何与方向映射来源；新能力协商；执行授权不依赖图片；journal/结果查询语义；自身模型入口的坐标单位 |
| Gadget 固件 | 内部运行管理、内存核对与回收策略和串行调度；九工具最终注册预算；禁止重放；完整配置与配对保留 |

Gadget 当前结论：设计方向可行，Actell 必须适配；注册最终预算、重启后核对存储方案及 Muse 平台 ID/参数能力尚需确认，不能据此宣布已可直接实施。
